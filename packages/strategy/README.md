# Профили, форматы и условия цены

Дата: 2026-10-04. Локальный `partner-strategy-1`, без сторонних зависимостей и сетевых вызовов. [Логика и аудит](../../docs/product/profil-partnera-i-format.md).

## Запуск

```powershell
python sponsor.py strategy --brief packages/strategy/examples/brief-partial.json --format html --out data/exports/profile-partial-v1.html
python sponsor.py strategy --brief packages/strategy/examples/brief-synthetic.json --economics packages/strategy/examples/economics-synthetic.json --format html --out data/exports/profile-synthetic-v1.html
python sponsor.py strategy --id RESEARCH_ID --format json --out data/exports/profile-saved-v1.json
```

`--brief`: объект с `title`, `kind` (`synthetic`/`owner_brief`), исходным `request` и `brief`; база не открывается. `--id`: существующая SQLite через `mode=ro`, без изменения ревизий/решений. Выход: `markdown`, `html`, `json`; существующий файл не перезаписывается. Примеры полностью синтетические и не задают ставки реальных кампаний.

`GET /api/research/ID/strategy` показывает отчёт из сохранённого брифа без финансового файла. CSP кабинета сохраняется; автономный HTML включает стиль и входы. Экономика форматов пока вводится через CLI, отдельной финансовой формы в кабинете нет.

## Настройки

Необязательный `brief.search_preferences`:

| Поле | Значения / умолчание |
| --- | --- |
| `categories` | `creators`, `athletes`, `music`, `teams`, `events`, `gaming_media`; все |
| `lanes` | `direct`, `audience`, `adjacent`; все; косвенная тема требует `term` и `reason` |
| `languages` | `es`, `pt`, `en`; пустой массив = языковой пакет страны |
| `formats` | `content_series`, `ambassador`, `event_activation`, `season_program`, `licensed_content`; все |
| `order` | `balanced`; альтернатива `focused` — порядок углов, категорий и стран |
| `max_profiles` | Целое 1–5, по умолчанию 3; объём отчёта, не отсечение кандидатов |
| `capabilities` | `content_owner`, `ongoing_owner`, `event_team`, `paid_media`, `conversion_tracking`, `brand_measurement`; `true`/`false`/`null` |

Пустой набор категорий/углов/форматов отклоняется. Неподдерживаемые GEO видны отдельно; известные обрабатываются. Категории пересекаются с допустимыми для выбранных форматов. Соответствие типов и порядок форматов — авторская гипотеза, не эмпирическое правило.

Малый лимит распределяется между GEO, углами и категориями; первичные языки идут раньше переводов. `scheduled` — выделенные ячейки, а не разрешение повторно потратить лимит. `execution.next_queries` исключает выполненные и неудачные ячейки текущей версии; `retry_requires_review` показывает неудачные отдельно. Остаток учитывает завершённые/неудачные вызовы и страницы **всех версий**. Неудачи не считаются покрытием. Перед реальным вызовом заново проверить лимит, после — зарегистрировать `record_search`.

## Экономика форматов

`--economics` содержит `brief_sha256` и `profiles`, где ключ — ID формата. Хеш берётся из первого отчёта по нормализованному брифу. При изменении брифа нужно пересмотреть допущения, а не механически заменить хеш. Экономика одного формата не переносится на другой.

Обязательны совпадающие с брифом валюта, период и GEO; `other_cost_scope_complete`, пояснение полноты, семь непересекающихся категорий без гонорара: производство, активация, платное продвижение, измерение, поездки/комиссии/налоги, внутренняя работа, прочее. Также нужны определения и интервалы маржи и добавочного результата, целевой ROI в долях.

Интервал: `low`, `high`, `status`, `source`, `as_of`, `note`, как в [measure](../measurement/README.md). Неприменимость = явный ноль с основанием; неизвестность = `status: unknown`, обе границы `null`. Числа конечные; отдельные суммы для вычисления ограничены 10¹². Нельзя дублировать расходы в марже и затратах кампании.

Для бюджета B, прочих затрат O, добавочного результата N, маржинального вклада m и целевого ROI r:

- Бюджетный потолок гонорара `all_in`: B − O. При `fee_only`: B, полная стоимость = B + O.
- Экономический потолок: N × m / (1 + r) − O.
- Совместный потолок: минимум этих ограничений.
- Результат при полном расходовании бюджета: `ceil(C × (1+r) / m)`, где C = B для `all_in`, C = B + O для `fee_only`.

Границы — экстремумы допущений, не доверительный интервал и не диапазон рыночной цены. Нижний потолок — консервативный сценарий; верхний требует благоприятных исходов. Отрицательные значения сохраняются: даже нулевой гонорар не подходит в этом сценарии. При нулевой/неизвестной нижней марже конечный гарантированный порог не рассчитывается. Неполные затраты блокируют экономический потолок; известный лимит `fee_only` остаётся только ограничением гонорара.

В примере B = 180 000 USD за 12 месяцев, O = 40 000, m = 100–120, N = 1 200–1 800, r = 20%. Потолок по бюджету 140 000, по экономике 60 000–140 000; при полном расходовании бюджета нужно 1 800–2 160 добавочных результатов. Это арифметика придуманных условий, она не доказывает достижимость и ставку.

Входы и хеш сохранены в отчёте. Строка `observed` не доказывает причинность: основания и дизайн проверяет человек. Брендовая цель без надёжного перехода к добавочной марже не получает финансовый ROI. Ставку и доступность отдельно запрашивает у правообладателя человек.
