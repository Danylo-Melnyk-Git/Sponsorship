# Расчёт экономики и измерений `measurement-1`

Дата: 2026-10-04. Стандартная библиотека Python 3.12+, без сети, установки библиотек и записи в SQLite. [Методика, дополнительные углы и порядок пилота](../../research/izmerimaya-ekonomika/README.md).

## Запуск

```powershell
python sponsor.py measure --file packages/measurement/examples/synthetic.json --format html --out data/exports/my-measurement/report.html
python sponsor.py measure --file packages/measurement/examples/synthetic.json --format json --out data/exports/my-measurement/report.json
python sponsor.py measure --file packages/measurement/examples/synthetic.json --out data/exports/my-measurement/report.md
```

Существующий файл не перезаписывается. HTML открывается локально, не загружает внешние ресурсы; раскрытие исходных данных работает без JavaScript. Расчёт выполняется CLI, HTML — готовый отчёт, не редактор входов. В основной веб-кабинет формы финансовых расчётов ещё не встроены.

Для рабочего кейса скопировать [template.json](examples/template.json) в `data/private/`, заменить паспорт, даты и целевой ROI, заполнить известные входы и назвать файл по пакету/версии. В шаблоне все финансовые входы неизвестны, финансовый итог не вычисляется. [synthetic.json](examples/synthetic.json) содержит только вымышленные числа. Пользовательские данные не помещать в examples.

## Контракт

Обязательные поля: `schema_version="measurement-1"`, `kind=synthetic|planning`, `title`, `scope`. Нужен минимум один блок: `economics`, `survey`, `sample_plan`, `audience`, `ratings`. Неизвестные поля отклоняются, чтобы ошибка названия/единицы не проходила молча.

`scope`: валюта (3 заглавные буквы, список ISO автоматически не проверяется), территория и конкретный пакет, `period_start`/`period_end` ISO-датами, единица добавочного результата `outcome_unit`. Финансовые входы одного файла относятся к этому окну и валюте. Автоматической конвертации и дисконтирования нет. Для дробных результатов порог сейчас округляется вверх: единица должна быть счётной (клиенты, заказы), не денежной суммой и не процентными пунктами.

Каждый финансовый вход — объект:

```json
{
  "low": 80,
  "high": 120,
  "status": "assumption",
  "source": "Идентификатор файла, выгрузки, URL либо автора гипотезы",
  "as_of": "2026-10-04",
  "note": "Что измерено, за какое окно; метод границ, исключения и ограничения"
}
```

`status`: `assumption` — допущение; `estimate` — оценка с методом; `observed` — предоставленное наблюдение; `unknown` — неизвестно, обе границы null. Источник, дата и note обязательны и у неизвестного (например, «не предоставлен; запросить Finance»). Наличие этих строк не удостоверяет первичность и истинность. Программа проверяет структуру, не читает источник.

| Блок | Входы | Выходы / ограничения |
| --- | --- | --- |
| economics | `cost_scope_complete`, `cost_scope_note`, `margin_definition`, `incremental_outcome_definition`, `target_roi` (доля: 0.2 = 20%), `costs`, `margin_per_outcome`, `incremental_outcomes`, необязательный `alternative_net` | Полный бюджет при отсутствии неизвестных, пороги, сценарный ROI, цена прав, разность чистых результатов, чувствительность. Добавочный исход может быть отрицательным; цена прав тоже. Поле подтверждённого причинного ROI всегда false |
| costs | Ровно `rights_fee`, `production`, `activation`, `paid_media`, `measurement`, `travel_fees_taxes`, `internal_work`, `other` | Каждая статья — отдельный непересекающийся интервал, неотрицательные расходы. Ноль с объяснением, неизвестное null |
| survey | `metric`, `population`, `period`, `design_note`, `design`, `alpha`, `treatment`/`control` с `yes` и `n`; `source`, `as_of`, `note` | Доли, разница в п.п., относительная разница; Wilson/Newcombe для независимых групп. Нулевой control даёт null относительной разницы |
| survey.design | `randomized_individual`, `observational_independent`, `clustered_or_weighted_or_paired` | Последний режим не рассчитывает наивный интервал. Для взвешенного survey сырые `yes/n` — только невзвешенное описание; веса не принимаются. Причинность ни в одном режиме автоматически не удостоверяется |
| sample_plan | `baseline_rate` (доля), `effect_pp` (положительный эффект в п.п.), `alpha`, `power`, `response_rate`; `source`, `as_of`, `note` | Приближённое n на группу и приглашения для равных независимых групп; не кластерный/панельный расчёт |
| audience | Общая `population`, `reach_a`, `reach_b`, `overlap` (число или null), `population_definition`, `period`, необязательные `target_marginal_shares`; `source`, `as_of`, `note` | Границы пересечения, объединения, новых людей B и совместной доли признаков. Доли 0–1, все должны относиться к одной исходной популяции |
| ratings | `rater_a`, `rater_b`, `rubric_version`, `rows` с уникальным `id` и оценками `a`/`b` 0–100 или null; `source`, `as_of`, `note` | Полные пары, пропуски, точное совпадение, абсолютный/направленный разрыв и проблемные пары. Исходы оценщиков не заменяются консенсусом |

Финансовые суммы и счётчики ограничены по модулю 10¹², NaN/Infinity/bool вместо чисел отклоняются. Возвраты учитываются в марже/определении расходов; отрицательные статьи затрат не поддерживаются. Не вводить отрицательные расходы для сокрытия субсидии/пересечения — пересобрать сопоставимую чистую стоимость с Finance и описать метод.

JSON-отчёт содержит исходные входы и SHA-256 их канонического представления. Это воспроизводимость вычисления, не подпись первичного источника и не доказательство достоверности. Разные даты/состав бюджета/версии пакета должны получать новый вход и новый экспорт.

## Связь с текущим проектом

`diagnose` продолжает проверять устойчивость scorecard по сохранённому исследованию. `handoff` формирует запросы по его пробелам. `measure` принимает отдельный файл и не меняет исследования, решения людей или версии весов. Автоимпорт из плана измерения/реестра прав не реализован: копирование входов требует сверки единиц, дат, состава и источников.

Проверка: `python -m unittest discover -s tests -p test_measurement.py -v`; полная — `./scripts/verify.ps1`. [Протокол](../../tests/proverka-izmereniya-2026-10-04.md).
