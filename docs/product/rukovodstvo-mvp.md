## Запуск

Из корня проекта:

```powershell
python sponsor.py serve --port 8176
```

Или .\scripts\start.ps1. Открыть [кабинет](http://127.0.0.1:8176). Остановка — Ctrl+C в терминале запуска. Другая база указывается перед командой:

```powershell
python sponsor.py --database data/qa/example.sqlite3 serve --port 8177
```

Python 3.12+ достаточен; pip/npm install не требуется. Данные сохраняются между запусками. Кнопка демонстрации создаёт отдельное исследование с вымышленными кандидатами, ценами и показателями. Рабочий бренд создаётся отдельно.

Для скачивания отчёта или пакета для отделов в PDF установите дополнительный пакет: `python -m pip install -r requirements-pdf.txt`. Экспорт запускается одной кнопкой и сразу сохраняет файл; печать не открывается.

## Начать из чата

Можно написать: «Нужен амбассадор для бренда X, Чили, спорт, бюджет 200 тысяч в год». В этом проекте Codex превращает сообщение в бриф, сохраняет через CLI и возвращает ID исследования.

Неуказанная валюта, «в месяц или год» и непонятный состав бюджета остаются вопросами. Для перехода к поиску нужны компания, продукт, цель, ЦА, GEO, сумма, валюта, период и состав бюджета: all_in или fee_only.

«18+ и платежеспособные» — отправная гипотеза. Исследователь предлагает проверяемые сегменты по интересам, географии, возрасту и поведению. Доход не выводится из профессии автора или популярности спорта. Заявление владельца о лицензии сохраняется как предоставленное сведение в licence_note.

Исходное сообщение в браузере сохраняется текстом. Автоматическое извлечение всех полей внутри приложения пока отсутствует; эту работу выполняет Codex. Для продолжения в новом чате достаточно ID или названия исследования: ассистент сначала читает сохранённое состояние.

## Шесть этапов

| Этап | Действия | Условие перехода |
| --- | --- | --- |
| 1. Бриф | Условия, цель, аудитория, лимиты, материалы | Обязательные условия уточнены |
| 2. Первичный отбор | Прямой, аудиторный и косвенный поиск; очереди с причинами | Владелец вручную выбрал пул |
| 3. Глубокий анализ | Досье выбранных, активации, пакеты, оценки с источниками | Фактическое разрешение C-level на текущий пакет и приоритеты |
| 4. Условия | Люди получают цену; новый ответ создаёт версию; коммерческие требования | Фактическое утверждение предложения, подтверждение обязательств, даты кампании |
| 5. Исполнение | Задачи, владельцы, сроки, следующий шаг, подтверждения | Отчётность можно собирать параллельно исполнению |
| 6. Результаты | Метрики и затраты с источниками; план/факт; выводы | Все записанные обязательства приняты или сняты с причиной |

Вкладки показывают материалы; процесс переходит отдельной кнопкой с серверной проверкой. Новая версия брифа до кампании возвращает процесс к брифу и требует пересмотра оценок.

## Поиск и роли

```powershell
python sponsor.py list
python sponsor.py show research-ID --full
python sponsor.py plan research-ID --out data/private/plan-v1.json
python sponsor.py task research-ID discovery --out data/private/discovery-task-v1.json
```

Выходной файл не перезаписывается: новой версии нужно новое имя. Контекст содержит роль, версию, бриф, допустимый пул, источники, лимиты и контракт результата. Ассистент выполняет запросы доступными инструментами и сохраняет фактический результат:

```json
{
  "research_id": "research-ID",
  "expected_revision": 2,
  "role": "discovery",
  "operations": [
    {
      "action": "record_search",
      "payload": {
        "query": "Фактически выполненный запрос",
        "provider": "Фактически использованный инструмент",
        "status": "completed",
        "pages_read": 1,
        "cost": null
      }
    }
  ]
}
```

```powershell
python sponsor.py apply-role --file data/private/discovery-result-v1.json
```

Пример показывает форму записи, а не проведённый поиск. Неизвестная стоимость не заменяется нулём. Источник хранит дату чтения, происхождение, фрагмент и доступ. search_lead означает находку, которая не доказывает числовой показатель, цену или оценку. Недоступные страницы и противоречия сохраняются явно.

Роли: planner, discovery, dossier, analyst, reviewer, manager, measurement. Глубокие роли получают выбранный пул. Роль не выбирает кандидата, не записывает согласование человека, не начинает кампанию и не принимает обязательство. Она передаёт риск на проверку, но не снимает подтверждённый человеком блок.

## Пакеты и коммерческая проработка

Пакет задаёт кандидата, территорию, месяцы, активации, права и отчётность. Цена бывает неизвестной, оценочной, полученной или опубликованной. Оценочная вилка требует сопоставимых данных и метода переноса. Без подходящих аналогов цена остаётся неизвестной.

До передачи менеджеру определяют обязательные результаты, заменяемые активации, бюджет производства/измерения и права. Прогноз требует истории сопоставимых брендированных размещений и допущений; подписчики не превращаются в просмотры или продажи.

Менеджер уточняет представителя, доступность, срок действия цены, календарь, территорию, эксклюзивность категории, использование контента в рекламе, порядок согласования, отчётность, приёмку, переносы/замены и оплату. Ответы сохраняются материалами и описанием прав. Юридический текст готовит специалист.

Новый ответ с другими правами, активациями, сроком или территорией сбрасывает оценки и прогноз. Полученная цена меняется новым предложением. После редактирования пакета или весов нужно новое решение. Запись решения фиксирует уже состоявшееся решение человека; приложение не подписывает договор.

## Исполнение и результаты

Еженедельный список показывает просрочки, ближайшие семь дней, блокировки и задачи на приёмке. Приёмка/передача на проверку требуют материала; снятие обязательства — причины.

Обязательства вводятся и проверяются вручную. Программа не доказывает, что весь договор перенесён в задачи. По архиву roadmap подготовлен [процесс активации после подписания](aktivaciya-posle-podpisaniya/README.md), общий каталог пулов и шаблон кампании. Реестр количественных прав, подтверждения поручений, зависимости и новые правила повестки ещё не реализованы как отдельные функции MVP. Напоминания по расписанию ещё не настроены.

Показатель содержит метрику, период, значение и источник. Частичные наблюдения сохраняются отдельно. Итог сравнивается только за совпадающие даты кампании и в тех же единицах. Уникальный охват требует метода пересечений; для полных затрат проверяется валюта.

Закрытие кейса фиксирует «продлевать / изменить / завершить» и уроки. Пустые фактические показатели остаются пустыми; закрытие не превращает их в успех. Причинный ROI требует добавочной маржи, полных затрат и подходящего сравнения; текущий MVP его не рассчитывает.

## Диагностика устойчивости

Для сохранённого исследования можно проверить, меняется ли предпочтение при других допущениях. Команда читает базу только в режиме `mode=ro`, не создаёт базу при ошибке пути и не меняет revision, веса, риск или решения.

```powershell
python sponsor.py diagnose research-ID --weight-radius 5 --format html --out data/exports/diagnostika-v1.html
python sponsor.py diagnose research-ID --weight-radius 5 --score-radius 10 --format json --out data/exports/diagnostika-v2.json
```

`--weight-radius` обязателен: допустимое отклонение **каждого веса в процентных пунктах**, при сумме 100%. `--score-radius` задаёт отклонение пригодных оценок в баллах, по умолчанию 0. Оба параметра от 0 до 100. Значения 5 и 10 — примеры допущений, не валидированные настройки. Для Markdown параметр формата можно опустить. Существующий файл не перезаписывается.

HTML открывается в обычном браузере без установки библиотек и внешних ресурсов. Раскройте пару, чтобы увидеть веса и значения для обеих границ разности. Если диапазон пересекает ноль, предпочтение может измениться. Диапазон из независимых пропусков — возможные границы, не доверительный интервал. Условные границы места могут быть шире точного множества достижимых мест.

Риск, ручной выбор, актуальность брифа, бюджетные ограничения и сопоставимость проверяются до включения в диагностическое сравнение. Неизвестная цена показывается отдельным вопросом и не доказывает доступность пакета. Карта ссылок критериев помогает увидеть зависимость многих оценок от одного материала.

Новый синтетический пример с близкими лидерами создаётся отдельно от рабочей базы:

```powershell
python scripts/demo_diagnostics.py --database data/qa/diagnostics-example.sqlite3 --out-directory data/exports/diagnostics-example
```

Оба пути должны быть новыми. Генератор создаёт только вымышленные данные и три формата отчёта. [Методика, ограничения и карта дальнейших работ](../../research/ustoychivost-resheniya/README.md).
