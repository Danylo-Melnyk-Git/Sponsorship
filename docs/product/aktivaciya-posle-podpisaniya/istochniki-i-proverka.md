## Расхождения и принятые границы

1. **Разные владельцы процесса.** В таблицах часть задач закреплена за Media Buying, а процессный документ называет Sponsorship владельцем Delivery. Прямое описание пользователя в текущей сессии имеет приоритет: внешнюю и внутреннюю координацию ведёт Sponsorship. Реальные исполнители отделов ещё не назначены.
2. **Разная обязательность подключения функций.** В S01 некоторые отделы опциональны, в S02 они перечислены как отдельные шаги. В общем процессе обязательно рассмотреть пул; конкретные работы назначаются по применимости. Условные ветки не превращены в обязательные для всех партнёров.
3. **Смешение партнёров в одном чек-листе.** Название S04 и часть его содержания относятся к разным объектам; лист Contract details содержит только заголовки. Эти строки подтверждают типы работ, но не права, объёмы или принадлежность условий конкретному партнёру.
4. **Похожие версии и повторяющиеся строки.** S06/S07 и S08/S09 пересекаются. Они объединены по смыслу, а не просуммированы как разные обязательства. Актуальную версию для живой кампании нужно назвать отдельно.
5. **Исторические сроки и статусы.** Трёхдневная оплата, даты матчей, количества публикаций и статусы Done относятся к исходникам. Они не становятся настройками будущего договора.
6. **Закрытие материалов.** S01 предлагает бессрочную работу контента в открытых источниках. В новом процессе хранение и продолжение публичного/рекламного использования проверяются по действующим условиям; универсальное бессрочное право не предполагается.
7. **Каналы и продуктовые примеры.** Специальные каналы, спортивные/казино-механики и альтернативные продуктовые ветки из архива сохранены как контекст применимости. Их наличие в файле не утверждает новый медиаплан и не заменяет профильную проверку конкретного запуска.

## Проверка на сценариях

Это проверка полноты описания, выполненная при подготовке документа. Программные сценарии и реальные внешние отправки не исполнялись.

| Сценарий | Ожидаемый результат процесса | Где предусмотрено |
| --- | --- | --- |
| Партнёр уже подписан, исследование в MVP отсутствует | Можно подготовить план по материалам, не выдумывая прошлые решения | Процесс §2/§11; шаблон §1–§2 |
| Нужна ссылка для публикации | Есть владелец, конечная страница, метки, проверка, передача и отчёт | P07; пример цепочки |
| В контракте доступна съёмка, но идеи пока нет | Право остаётся видимым с остатком, сроком запроса и следующим решением | Процесс §3/§7; шаблон §4 |
| Отдел получил сообщение, но не назначил человека | Задача остаётся неподтверждённой; у Sponsorship есть контроль ответа | Процесс §5–§7; шаблон §7–§9 |
| Публикации повторяются каждый месяц | Каждый период имеет отдельное исполнение; один закрытый пост не закрывает весь срок | Процесс §2/§7; шаблон §3 |
| Матч перенесли, срок права остался прежним | Сдвигаются относительные задачи, конфликт с фиксированной датой виден | Процесс §4/§10 |
| Публикация вышла, статистики ещё нет | Исполнение принимается по доказательству; результат остаётся неизвестным до отчёта | Процесс §8–§9; P06/P15 |
| Новый монтаж после согласования | Нужна проверка согласования новой версии; старое не применяется автоматически | Процесс §6/§10 |
| Одно право пытаются использовать в двух активностях | Подтверждённый резерв учитывается; нет двойного списания | Процесс §3; шаблон §4 |

| Отменена задача или изменился срок | Будущие напоминания отменяются/пересчитываются, история сохраняется | Процесс §7 |
| Кампания завершена, реклама продолжает использовать образ | Отдельно проверяются срок прав, отключение и основание дальнейшего использования | Процесс §10; P16 |

## Что нужно проверить на пилоте

Пройти один актуальный контракт с Sponsorship: полноту переноса пунктов, применимость всех пулов, реальность сроков подготовки, полномочия принимающих и удобство личной повестки. Затем получить обратную связь хотя бы от затронутых отделов. До этого каталог и правила — подготовленный рабочий вариант, а не утверждённый регламент компании.
