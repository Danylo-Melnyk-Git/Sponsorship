# Поручения для работы с неопределённостью

Дата: 2026-10-01. **Шаблоны, не выполненные исследования и не запуск агентов.** Один ассистент может выполнять их последовательно. Конкретные ID, пути и версии берутся из сохранённого состояния.

## Общий вход для любого поручения

```text
Работай с исследованием <ID>. Прочитай README.md, PRIORITIES.md,
руководство MVP и актуальные правила проекта.
Выполни list, затем show <ID> --full. Не создавай новый бриф вместо существующего.
Получай задание через task <ID> <ROLE>; используй фактическую revision.
Проверь остаток лимитов до каждого сетевого вызова. Сохраняй выполненные
запросы, попытки чтения, доступ, дату и неизвестную стоимость как null.
Не записывай решения людей, выбор пула, согласование или снятие риска.
Результат роли импортируй через apply-role. При конфликте перечитай изменения
и согласуй результат; не подставляй новый номер версии механически.
```

## 1. Проверить основание, которое способно изменить сравнение

Роль: `reviewer`. Входы: снимок исследования, результат `diagnose`, конкретный пакет и критерий.

```text
Проверь основание критерия <CRITERION> пакета <PACKAGE_ID>.
Диагностика указывает на чувствительность, но не является доказательством
правильной оценки. Не подгоняй значение под победу или порог.
Для каждого существенного утверждения верни:
1) точный смысл и статус: измерение / заявление стороны / гипотеза / вывод;
2) источник, прочитанный фрагмент, дату, период и популяцию;
3) что именно этот источник подтверждает и чего не подтверждает;
4) противоречия, общую первооснову нескольких ссылок и ограничения доступа;
5) допустимое исправление или явный пробел, затем вопрос для человека.
Не превращай национальность автора в географию аудитории, подписчиков —
в брендированные контакты, а поисковый сниппет — в прочитанный источник.
Применяй только операции, разрешённые текущим task/контрактом reviewer.
Если исправление пакета не разрешено роли, передай его как предложение analyst.
```

Результат принимается, если вывод прослеживается до источника и неизвестное остаётся неизвестным. Заполненное поле не считается качественным только потому, что оно заполнено.

## 2. Разобрать смену предпочтения

Роль: `analyst`. Входы: два сопоставимых пакета и точная область допущений.

```text
Сравни <PACKAGE_A> и <PACKAGE_B> при брифе v<BRIEF_VERSION>.
Используй текущие веса; для диагностики только задай отклонение <R> п.п.
и отклонение пригодных оценок <D> баллов. Не меняй веса исследования.
Покажи: исходные баллы, допуск, пропуски, минимум/максимум разности,
конкретные веса и значения в крайних сценариях, экономические условия отдельно.
Объясни словами, какой компромисс меняет предпочтение: аудитория, доставка,
соответствие бренду или права/исполнение. Раздели нехватку фактов и различие
предпочтений владельца. Не называй частоту сценариев вероятностью успеха.
Если имеющихся материалов недостаточно для новой оценки — сохрани пробел.
Выход: два-три вопроса, ответ на которые поможет человеку принять решение.
```

Результат принимается, если расчёт воспроизводится из одной версии и ни одно ограничение не компенсируется баллом.

## 3. Подготовить независимую оценку рубрик

Это подготовка материалов, а не имитация второго человека.

```text
На одном зафиксированном наборе <MATERIAL_SET> подготовь две одинаковые
пустые формы для независимых оценщиков. Не заполняй их от лица людей.
Покажи бриф, пакет, определения 0/25/50/75/100, источники и ограничения;
скрой текущий итоговый рейтинг и оценки другого человека.
Для каждого критерия нужны оценка или null, основание, ID источника,
причина неопределённости и вопрос. Отдельно проверяются жёсткие условия.
После получения фактических ответов сохрани обе исходные формы.
Разложи расхождения на: разные материалы, неоднозначная рубрика,
разные фактические выводы, разные предпочтения. Не усредняй конфликт молча.
Не рассчитывай коэффициент согласия без подходящей выборки и шкалы.
Выход: исправления формулировок и протокол повторной независимой оценки.
```

## 4. Превратить пробел оффера в поручение менеджеру

Роль: `manager`. Только подготовка; обращения выполняет человек.

```text
Для оффера <OFFER_ID/PACKAGE_ID> составь вопросы по отсутствующим условиям.
Используй фактическую валюту и период; при их отсутствии спроси, не предполагай.
Для каждого вопроса укажи влияние на решение, нужное подтверждение
и зависимость от других вопросов. Проверить: состав активов, территории,
период, права использования, эксклюзивность, календарь, доступность,
цену/срок её действия, производство, активацию, измерение и полноту затрат.
Предложи вопросы о заменах при срыве и о подтверждении исполнения;
не создавай юридический текст и не выдавай наличие права за установленный факт.
Раздели обязательные уточнения и полезные дополнения. Подготовь текст
для менеджера, но не отправляй его кандидату и не регистрируй сделку.
```

## Универсальные причины остановить конкретный вывод

| Ситуация | Что сохранять вместо уверенного заключения |
| --- | --- |
| Страница недоступна / есть только находка | Статус доступа, попытку чтения, вывод «не проверено» |
| Популяция, период или актив не совпадают | Причину несопоставимости и запрос нужных данных |
| Разные источники противоречат друг другу | Обе версии, их даты и вопрос на проверку |
| Общий медиакит процитирован разными сайтами | Общую первооснову; не считать независимыми подтверждениями |
| Изменились бриф, права или период пакета | Новую версию и необходимость переоценки |
| Недостаёт реальных аналогов цены | Неизвестную цену и перечень нужных сопоставимых условий |
| Лидер зависит от спорного веса | Компромисс для владельца, без автоматической подгонки |

Протоколы не заменяют существующий [контракт ролей](../../agents/workflow.json) и [руководство](../../docs/product/rukovodstvo-mvp.md).
