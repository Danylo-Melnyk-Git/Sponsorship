# Поиск, анализ и подбор амбассадоров и спонсорских объектов

Дата: 2026-09-30. Версия: 0.1. Статус: рабочий исследовательский прототип по заданию владельца. Исполняемый инструмент строит план и проверяет досье; поиск и извлечение выполняет исследователь в Codex через доступные инструменты. Технический стек веб-продукта и постоянный поставщик данных не выбраны.

- [Контракт данных](kontrakt-dannykh.md): версия брифа, объект, конкретный пакет, доказательства, неизвестные и бюджетная гипотеза.
- [Инструкции исследовательских ролей](../../agents/poisk-i-podbor.md): планировщик, поиск, извлечение, сопоставление, бюджет, проверяющий. Роли можно выполнять последовательно одним исследователем; этот документ не разрешает запуск отдельных агентов.
- [Каталог инструментов и источников](istochniki-i-instrumenty.md) с проверенными ограничениями.
- [Проверочный прогон Чили](proverka-chili-2026-09-30.md), [публичные досье](primery/dose-chili-public.json) и [очередь отбора](rezultaty/otbor-chili-demo-2026-09-30.md).

## Вход и результат

Рабочий вход: компания/продукт, цель, ЦА, целевое GEO, сумма и валюта бюджета, период, состав бюджета и ограничения. Пример «$100 тысяч в год» из задания не принят за реальный бюджет. [Пример брифа](primery/brif-chili-demo.json) использует условный бренд активного отдыха только для проверки процесса.

Из описания бренда исследователь формирует темы и связи в topics. Код не понимает бизнес автоматически и не заменяет этот шаг. Если бренд или аудитория ещё не заданы, допустима разведка источников, но брендовый shortlist пока не обоснован.

Единица сравнения: **версия брифа + кандидат + конкретный пакет + территория + период**. У одного спортсмена можно исследовать годовое амбассадорство и отдельную интеграцию; у гонки — титульное спонсорство и партнёрство небольшой зоны. Их цена, доступность и эффект различаются.

Выход — очередь дальнейшего исследования с объяснением связи, проверкой порога, состоянием GEO аудитории, бюджетным статусом, риском, источниками и вопросами менеджеру. Это первый этап перед общей [аналитикой](../metodika-sessiy-3-10/moduli-ocenki-vesov-i-prognoza.md), ручной модерацией и C-level. Численный рейтинг эффективности и прогноз ROI здесь не рассчитываются.

## Логика обнаружения

Матрица поиска состоит из шести направлений:

1. Авторы, инфлюенсеры и эксперты.
2. Спортсмены, включая специализированные дисциплины.
3. Музыканты, артисты и независимые лейблы.
4. Команды, клубы, лиги и федерации.
5. Турниры, события, гонки и фестивали.
6. Киберспорт, стримеры, подкасты и тематические медиа.

В каждой категории проходят три угла:

| Угол | Что искать | Как объяснять |
| --- | --- | --- |
| direct | Прямую связь с продуктом/категорией | Какой контент или актив соединяет объект и бренд |
| audience | Совпадение интересов и контекста ЦА | Какие сведения поддерживают совпадение аудитории |
| adjacent | Косвенную связь, которую обычно пропускает поиск «топовых» имён | Мост: бренд → потребность/ситуация ЦА → тема/актив кандидата; что может опровергнуть мост |

Для Чили основные запросы испанские, дополнительные — английские; для Бразилии основные португальские. По умолчанию 18 запросов закрывают 6 направлений × 3 угла на основном языке Чили; ещё 18 англоязычных остаются в deferred. При расширении GEO число ячеек растёт: лимит не исчезает, незапущенные направления сохраняются явно. Лимит не является обещанием полноты рынка.

После первоначального поиска исследователь:

- Открывает официальные профили, федерации, календари, составы участников, агентские roster и страницы организаторов.
- Из перспективного объекта делает дополнительные переходы: связанные дисциплины, гости, другие участники, организатор, дочерние соревнования, тематические авторы.
- Ищет текущие рекламные сотрудничества, формат контента и доступные измерения аудитории.
- Отдельно ищет риски/конфликты категории и актуальные опровержения.
- Меняет стратегию, если выдача состоит из коммерческих «топов» или одинаковых знаменитостей.

Найденная поиском ссылка — lead. Утверждение появляется в досье только после чтения страницы с фрагментом и датами. Теги темы назначает исследователь по источнику; совпадение тегов в коде — прозрачный технический фильтр, а не доказательство совпадения ЦА.

План на диске содержит точные аргументы доступного Exa MCP. Это конфигурация запуска в Codex, не фоновая интеграция приложения. Возобновление: работать только с ещё не выполненными ID плана и записывать результат в журнал; не делать платные повторы молча.

## Порог подписчиков

Согласовано владельцем 2026-09-30:

- По умолчанию 100 000 на хотя бы одной платформе.
- Аудитории платформ и отдельных аккаунтов не суммируются.
- Порог доступен в advanced.min_followers и через --min-followers.

В прототипе порог действует для типов influencer и streamer. Список типов настраивается через follower_gate_kinds. Клуб, команда, артист, спортсмен или событие оцениваются как отдельный медийный объект; для них число подписчиков не подменяет посещаемость, просмотры, медийную активность и доступные активы. Подробные критерии медийного масштаба этих типов ещё предстоит проверить.

Скрытый, отсутствующий, устаревший или противоречивый счётчик → pending. При округлении на границе нужны подтверждённые границы числа, иначе pending. Отсечение по низкому числу возможно только при явно завершённой проверке платформ, указанных в досье. Предварительный срок свежести счётчика — 7 дней из действующего проекта [политики свежести](../modul-onlayn-resercha-i-aktualizacii-dannykh.md); это настраиваемое предложение, не установленный SLA.

## GEO и соответствие бренду

Место рождения автора, язык контента, домен .cl и место события не равны географии аудитории. Отдельно сохраняются geo_context и audience_geo. Зафиксированные данные поставщика остаются оценкой поставщика, а медиакит — заявлением стороны.

Нужно выяснить долю/размер ЦА в нужном GEO, период, определение аудитории, соответствие возрасту/интересам и активность. Для международного события отдельно изучать местных посетителей, приезжих, онлайн-зрителей и публикации. Гипотеза косвенного соответствия должна иметь понятный сюжет и проверку; одной темы недостаточно.

Сам инструмент возвращает supported только как наличие указанного исследователем подтверждения GEO в audience_geo, без оценки размера/доли или достаточности для бренда. Решение о достаточной доле и совпадении ЦА остаётся за модератором.

## Бюджет при неизвестной ставке

Гонорар отделён от активации, производства, прав, агентской комиссии, поездок, измерения и других расходов. При all_in неизвестные расходы сверх гонорара не превращаются в ноль.

| Состояние | Как поступать |
| --- | --- |
| Нет ставки, есть ограниченный пакет | limited_package_to_price: можно исследовать, доступность по цене не установлена |
| Аналитик обосновал правдоподобие под конкретный бриф/сумму | plausible_unpriced: гипотеза, без придуманного ценника |
| Аналитик считает бюджет маловероятным | unlikely_unpriced: нижний приоритет/другой пакет; не утверждать превышение цены как факт |
| Изменился бриф, сумма, период или состав бюджета | reassess_budget_hypothesis: пересмотреть предположение |
| Глобальная эксклюзивность без ставки | global_exclusive_requires_quote: не ставить в основную очередь как доступное сотрудничество |
| Есть сопоставимый ценовой диапазон | Проверить валюту, период, территорию, права и состав расходов; сохранить источник и статус published/estimate |
| Диапазон целиком ниже/выше потолка либо пересекает его | within_observed_range / over_observed_range / overlapping_range |
| Известен только гонорар при полном бюджете | need_full_cost: нужны остальные расходы |

Классы масштаба local/niche/international — описание исследователя, не таблица рыночных ставок. Автоматический вывод «нишевый значит дешёвый» отсутствует. Бюджетная гипотеза фиксируется отдельно с ID брифа, суммой, валютой, периодом, составом бюджета, основаниями и допущениями; она не переносится на бюджет $1 или другой бренд.

Нельзя оценивать годовую эксклюзивность по цене одного поста, выступления, билета, курса или стоимости товара. Сравнение цены требует именно цены сотрудничества. Если появятся аналоги, сохранить количество активаций, права, территорию, период, источник, дату и расчёт переноса. Численный диапазон не заполнять, пока перенос нельзя объяснить. Это согласуется с [методикой пакета и аудита](../metodika-sessiy-3-10/paket-i-audit-offera.md).

Для примера «$100 тысяч в год и мировая знаменитость» система не объявляет реальную ставку: глобальный эксклюзивный пакет без цены остаётся в needs_data. Разумный следующий поиск — другой масштаб и ограниченные права/активации. Реальная готовность к сделке выясняется людьми.

## Очереди и дедупликация

- research_priority: есть тематическое основание и нет установленного препятствия; очередь углублённого исследования, не готовая рекомендация.
- alternative: косвенная связь или другой вариант для проверки.
- needs_data: неподтверждённый порог, конфликт, прошлое событие, необоснованная связь либо пересмотр бюджета.
- excluded: подтверждённый провал порога, сопоставимый диапазон выше бюджета или проверенное человеком стоп-условие. Причина сохраняется.

Совпадение имени не объединяет сущности. Участник, команда, организатор, редакция события, профессиональный клуб и одноимённая общественная корпорация различаются. entity_key назначается после проверки стабильного аккаунта/официальной идентичности. Полностью одинаковые досье с одним ключом исключаются как дубликаты с журналом. Разные сведения с одним ключом вызывают ошибку для ручной сверки; противоречия не затираются.

## Запуск

Из корня проекта, в PowerShell:

~~~powershell
python -B research/poisk-i-podbor/instrument-poiska.py plan --brief research/poisk-i-podbor/primery/brif-chili-demo.json --out research/poisk-i-podbor/rezultaty/novyy-plan.json

python -B research/poisk-i-podbor/instrument-poiska.py review --brief research/poisk-i-podbor/primery/brif-chili-demo.json --corpus research/poisk-i-podbor/primery/dose-chili-public.json --as-of 2026-09-30 --out research/poisk-i-podbor/rezultaty/novyy-otbor.json --markdown research/poisk-i-podbor/rezultaty/novyy-otbor.md

python -B -m unittest discover -s tests -p 'test_poisk_i_podbor.py' -v

python -B research/poisk-i-podbor/proverka-artefaktov.py
~~~

Существующий выход не перезаписывается. Для повторного запуска выбрать новое имя. Для нового бренда создать новый безопасный бриф; секреты, реальные офферы и рабочие персональные данные хранить вне отслеживаемых файлов. --as-of задаёт дату проверки; для нового живого исследования использовать его фактическую дату.

Выполнить матрицу поиска, проверить порог и аудиторию перспективных кандидатов, составить альтернативные пакеты и получить ручную оценку качества. Для цены нужны опубликованные пригодные аналоги либо обезличенные предложения. Контакт с кандидатами выполняют люди.
